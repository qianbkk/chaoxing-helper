# src/baseline/ —— 本仓库的基线

`chaoxing-helper.base.js` 是**本仓库补丁链的起点**：脱敏后的 **v1.8.2 发布件**。

## 它是什么

- 就是 v1.8.2 的发布件本体（本项目改造完成的那一版），只做了两处**不改变行为**的文字调整：
  ① 里面那行说明「v1.1 起移除了注入的第三方浏览器挖矿脚本」的注释，
  原本带着相关域名与账号，改成了不含域名与账号的表述；
  ② 同一行注释里的措辞改成中性说法（「早期版本」而不是具体出处），与本仓库文档的措辞保持一致。
- 除此之外**一行未改** —— 它是「我们改造到 v1.8.2 时的样子」的真实快照，
  后面每个版本都是在这份快照上打补丁。

## 为什么不用最早的脚本原件当基线

早期那条「来源脚本原件 → 逐版打补丁」的链，起点是**第三方二次打包**的版本，
里面带着注入的浏览器挖矿脚本，**不适合随包分发**。
（那两份发布在 Greasy Fork 上的脚本本身从来没有挖矿代码，坑在二次打包这一环。）
来源关系与安全结论见
[../../docs/来源与安全说明.md](../../docs/来源与安全说明.md)。

所以本仓库换了个起点：基线 = 已经做完改造、并且脱敏干净的自有产物。
早期版本（v1.1~v1.8.2）那条逐版打补丁的完整演进链保存在私有存档仓库
`qianbkk/scriptcat-chaoxing-helper` 里。

## 基线里还留着什么

基线是历史快照，所以它仍然保留**早期那两处第三方外发**的代码：

1. 刷视频时去第三方服务器取「签名令牌」，请求里带 `classId` / `UID` / 学习进度（明文 HTTP）；
2. 题库查不到时兜底去另一个地址查答案（开关硬编码为 0、面板无入口、服务器早已下线）。

**这两处在 `src/patches/patch-v1.9.0.ps1` 里被删除**（步骤 5），
所以**发布件 `dist/chaoxing-helper.user.js` 里已经没有它们** ——
`tests/release-meta.test.js` 里有两条断言专门守这件事，断言大意是：

```
发布件不再向第三方取签名令牌         （不含 getEnc.php）
发布件不再向第三方查答案             （不含 getAnswer.php）
本地 md5 分支仍在（进度上报改为本地算签名）
```

> 有意保留在基线里的原因：**改动过程可审计** ——
> 谁能看出我们删了什么、为什么删，而不是只看到一个「干净」的成品。
> 同理，基线与历史文档里可以保留取证原文，但这些内容**不得抄进发布件**。

## 之后怎么改

- 新版本：在 `src/patches/` 加一个 `patch-vX.Y.Z.ps1`，作用在基线（或上一个版本的产物）上；
- 整块功能模块：代码放 `src/modules/xxx.vX.Y.js`，由补丁用「起止标记区间」注入；
- 改完必须跑构建与全部测试：
  ```powershell
  pwsh -File src\build.ps1
  node tests\release-meta.test.js
  ```
  完整测试清单见 [../README.md](../README.md)。
