# 安装与自动更新

## 1. 准备 ScriptCat（脚本猫）

脚本是给 **ScriptCat** 写的。脚本里有一行自检：

```js
isCat = GM_info.scriptHandler == 'ScriptCat';
if (!isCat) { logs.addLog('推荐使用脚本猫运行此脚本，使用其他脚本管理器不保证能正常运行', 'orange'); }
```

所以在 Tampermonkey（篡过猴）里运行会持续打这条橙色告警，而且
`@storageName`、跨标签页状态同步这些 ScriptCat 专有能力在别的管理器下不保证。

- Chrome 应用商店搜「脚本猫」；扩展 ID `ndcooeababalnlpkfedmmbbbgkljhpjf`
- 装完**在扩展详情页打开「允许运行用户脚本」**
- ⚠️ 两个管理器同时装同一个脚本会互相抢 `.user.js` 的接管 —— 先关掉旧的再导

## 2. 安装

在浏览器地址栏打开：

```
https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.user.js
```

ScriptCat 会接管 `.user.js` 并弹出安装页，点「安装」。

> **必须通过 http(s) 打开**。用 `file://` 打开只会被当成纯文本渲染，不会触发安装。

### 下载慢 / 卡住不动？（2026-11-25 实测）

**只有「下载脚本文件」这一步可能需要代理；脚本跑起来之后不需要。**
脚本运行时访问的是 `cx.icodef.com`（icodef 题库）、`easylearn.baidu.com`（百度不挂科题库）、
以及超星自己的域名 —— 这些国内直连都通，**不需要挂代理**。

下载这一步的实测数据（同一台机器、同一份 `user.js`）：

| 路径 | 结果 |
|---|---|
| **jsDelivr（`cdn.jsdelivr.net`）** | **可用**：52–141 KB/s，5–14 秒，字节与发布件逐字节一致；**v1.11.5 起的正式安装地址与自动更新都走这条** |
| GitHub 直连 | **能连上但很慢**：13–25 KB/s，实测三轮里有两轮 30 秒超时只下到一半；`github.com` 网页本身也出现过 20 秒超时 |
| GitHub 走代理（7897） | **稳定**：130–153 KB/s，5 秒下完，三轮全部 200 |
| `ghfast.top` 镜像 | **可用**：152 KB/s，4.7 秒，字节一致 |
| `gh-proxy.com` 镜像 | **可用**：72 KB/s，9.9 秒，字节一致 |
| `gh.llkk.cc` / `ghproxy.net` / `gitclone` | **实测连不上**（30 秒超时） |

所以给朋友的话：**首选 jsDelivr 那个地址**（不用梯子）；
万一 jsDelivr 慢了或抽风，用下面任一备用地址，把 `https://github.com/qianbkk/chaoxing-helper/releases/download/`
换成对应前缀即可：

```
https://github.com/qianbkk/chaoxing-helper/releases/latest/download/chaoxing-helper.user.js
https://ghfast.top/https://github.com/qianbkk/chaoxing-helper/releases/download/v1.11.5/chaoxing-helper.user.js
https://gh-proxy.com/https://github.com/qianbkk/chaoxing-helper/releases/download/v1.11.5/chaoxing-helper.user.js
```

> ✅ **v1.11.5 起「自动更新」也不需要梯子了**：脚本的 `@updateURL` / `@downloadURL`
> 指向 jsDelivr（见 §4），朋友点「检查更新」走的是国内可直连的 CDN。
> 唯一的小代价是 jsDelivr 有几分钟到几十分钟的**缓存延迟** —— 刚发的新版可能要等一会儿。

## 3. 首次配置

打开超星课程章节页（`knowledge/cards`），页面会被替换成脚本面板。

面板分两块设置（左右并排），各存各的：

**「答题设置 · 题库」**：

| 项 | 说明 |
|---|---|
| 题库 Token | 选填，只影响题库并发（v1.11.3 实测：三个免费源都支持匿名查询） |
| 正确率门槛 | 默认 80%，自动提交门槛（按答完题的比例算） |
| 翻章模式 | 遍历（推荐）/ 不跳转 |

填完点「**保存题库设置**」。

> v1.11.3 起题库是**三个免费源一起查**（icodef、百度不挂科、icodef 备用源），谁先命中用谁；
> 题库地址写在脚本里，不需要也不接受配置。详见 [开发与构建.md](开发与构建.md) §「题库链路（v1.11.3 起）」。

**「答题设置 · AI 接口」**（可选，填了才能用 AI 兜底）：

| 项 | 说明 |
|---|---|
| Base URL | OpenAI 兼容接口根地址，例 `https://api.deepseek.com/v1`。**不要带** `/chat/completions`，脚本会自动拼 |
| 模型 | 例 `deepseek-chat` |
| API Key | 你的 key。**只存在你浏览器的 ScriptCat 存储里**，脚本文件本身不含密钥 |

填完点「**保存AI设置**」→「测试AI连通性」，看到 **AI连通性正常** 即可。

然后在章节测试处打开「自动答题」+「自动提交」。

### 想让它一路自己刷到底？

面板分**左右两栏**：

- **右边一栏 = 运行控制**（单独一个面板，紧挨「任务配置」的右方，滚动时一直挂在右上角）：
  - 「**开始/继续**」是绿色大号主按钮 —— 恢复自动翻章 / 作答 / 提交；
  - 「**暂停**」是红色小号按钮 —— 暂停后自动翻章 / 作答 / 提交全停，状态跨翻章保持；
  - 窄屏（手机）上这一栏会自动顶到最上面，不用往下滚才找得到；
- **左边一栏 = 各处配置**，其中「任务配置」里有「**全程托管**」勾选框（**默认关闭**）——
  遇到做不了的任务时自动跳过并记账，一路推进到最后一节。

> ⚠️ 托管模式的代价要说清楚：被跳过的章节，**任务点不会被点亮**；
> 闯关模式下超星可能因此不放行到下一节，这时脚本会持续重试并在日志里说明，
> 需要人工把那一节的任务点补上才能继续往下。
> 而且**直播任务即使跳过，也要超星那边自己到期才算完成**，脚本替代不了。

### 兼容哪些接口

任何 OpenAI 兼容的 `/chat/completions` 服务都行：DeepSeek、Kimi、智谱、MiniMax、通义、
OpenRouter、Ollama、本机 CLIProxyAPI 等。

> ⚠️ 推理型模型（MiniMax 等）会把**思考 token 计入 `max_tokens`**，额度给小了会返回空内容。
> 脚本已把上限放宽到 8000，并对 MiniMax 端点额外下发 `reasoning_effort: 'low'` 降思考深度。

### 阅读任务？（阅读助手，默认关闭）

「附加功能」面板里有一个「**阅读助手**」勾选框和「每段停留秒数」（**默认 10 秒**）。

打开它之后：

- 在**阅读正文页**（`/ztnodedetailcontroller/visitnodedetail`）打开时，脚本会收集正文元素
  （段落/标题/图/视频）并逐个滚过去，每段停「每段停留秒数」那么久；
- 读完当前这批之后会**滚到页面底部触发懒加载**，等后续内容加载出来就接着读，
  **一直读到加载不出新内容为止** —— 后半篇不会漏；
- 在**阅读任务目录页**（`/mooc-ans/zt/portal/` 等）打开时，脚本会自动找到目录里的阅读入口并点进去；
- 读完会写一行日志；页面里有「下一章」按钮时脚本会点它。

> 「每段停留秒数」从 v1.11.2 起默认是 **10 秒**。从 v1.11.1 升上来、还停在旧默认值 1 秒上的，
> 会被自动迁移成 10 秒；自己设过的值（比如 5 秒）不动。

> ⚠️ **它不能秒过**：全程不发任何完成上报请求 —— 超星是按**真实浏览时长**判定阅读任务完成的，
> 脚本只能把内容真的滚过去，读多久就是多久。
> 任务点已经亮过（这一节之前读过了）也一样照读 —— 目的就是把阅读时长拉满。
> 页面结构对不上时，脚本会记录「没找到正文内容」并放弃，不会乱滚。
> ⚠️ 本功能**未在真实超星页复验**：2026-11-25 在真实课程里确认了阅读任务是挂在章节卡片页上的
> 一个附件（`type=read`），但当时超星会话失效、没能打开阅读正文页 ——
> 所以「正文页判定能不能命中」与「懒加载续读」目前都仍是**未验证**。
> 页面形态与证据见 [开发与构建 §实测](开发与构建.md)。

### 调试模式（默认关闭）

「调试模式」面板里可以勾选。勾上之后，面板日志会**实时写到本机文件**，
并且可以**从命令行远程操控脚本**：

```powershell
node src/tools/log-sink.cjs      # 接收端，默认端口 8124，日志落到 logs/

curl -X POST http://127.0.0.1:8124/__cmd -H 'Content-Type: application/json' -d '{"cmd":"status"}'
curl 'http://127.0.0.1:8124/__log?tail=50'
```

支持 `pause` / `resume` / `status` / `reload` / `goto <chapterId>` / `set <key> <val>` /
`log <text>` / `dump` / `help`。

> 这是维护者自用的功能，公开版里代码保留但**默认关闭** —— 装了脚本不会往任何地址发请求。
>
> ⚠️ **调试变体与正式版不是一回事**：调试变体的版本号带 `-AI` 后缀，
> `@updateURL` 指向本机 `127.0.0.1:8124` —— 本机服务没开的时候，它**收不到任何更新**。
> 要换回正式版：地址栏打开下面这个地址，点「重新安装」即可。
>
> ```
> https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.user.js
> ```
>
> （jsDelivr 慢的话用备用通道：`https://github.com/qianbkk/chaoxing-helper/releases/latest/download/chaoxing-helper.user.js`）

## 4. 自动更新机制

脚本元数据里声明了两个地址：

```
// @updateURL    https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.meta.js
// @downloadURL  https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.user.js
```

发新版时把新版本提交到 `main` 分支（`dist/` 里的两个文件是提交进仓库的），
**已安装的用户点「检查更新」就能拿到新版**，元数据不用改。

### 为什么走 jsDelivr（v1.11.5 起）

「检查更新」是浏览器**直接请求** `@updateURL` 的。GitHub 在国内快慢极不稳定 ——
实测同一个地址直连只有 461–1068 B/s，715KB 的文件三轮里有两轮 30 秒超时下载不全，
于是「不挂梯子就更新不了，或者更新很慢」。

jsDelivr 是国内可直连的 CDN（实测 `cdn.jsdelivr.net` 三轮全 200），
读的就是本仓库 `dist/` 里的同一份文件。

> ⚠️ **代价**：jsDelivr 走 `main` 分支有**缓存延迟**（通常几分钟到几十分钟），
> 不是提交即到。发完新版如果朋友那边还显示旧版本，等一会儿再点一次「检查更新」。

### 备用通道：GitHub Releases

GitHub Releases **照常发版**，作为 jsDelivr 走不通时的备用：

```
https://github.com/qianbkk/chaoxing-helper/releases/latest/download/chaoxing-helper.user.js
```

手动打开这个地址装一次即可（脚本猫会接管 `.user.js`）。
另外两个实测可用的镜像前缀也可以套在同一个路径上：

```
https://ghfast.top/https://github.com/qianbkk/chaoxing-helper/releases/download/v1.11.5/chaoxing-helper.user.js
https://gh-proxy.com/https://github.com/qianbkk/chaoxing-helper/releases/download/v1.11.5/chaoxing-helper.user.js
```

### 为什么还要发 Release

`main` 上可能是实验性改动，推上去就会影响所有用户的更新；
发 Release 才是「这一版是稳定版」的明确动作。
`releases/latest` 永远指向最新的**正式** Release（预发布版不算）。

v1.11.5 起，`@updateURL` 走 jsDelivr（读 `main` 分支的 `dist/`），
但 **Release 照发** —— 它是 jsDelivr 走不通时的备用通道，也是「这一版是稳定版」的凭据。

### ScriptCat 的两个硬性要求

（读 ScriptCat 源码 + 本机实测确认）

1. `@updateURL` 与 `@downloadURL` **必须同时声明**，只声明一个不生效。
2. `@updateURL` 返回的内容会被 `parseMetadata()` 解析，所以它必须是
   **meta.js 那种「`==UserScript==` 元数据块」**，不是 Greasy Fork 的 JSON。
   这就是为什么 `dist/` 里要有两个文件：`.meta.js` 给检查更新，`.user.js` 给下载。

另外：不声明这两个地址时，ScriptCat 会把**安装地址**里的 `user.js` 换成 `meta.js` 去查更新 ——
所以两个资产的文件名必须成对（`xxx.user.js` / `xxx.meta.js`）。

### 静默更新的额外条件

ScriptCat 的静默更新要求**新旧版本的 `@connect` 域名集合没有新增**。
本脚本的 `@connect` 里已经有 `*`，所以不会出现「静默更新被拒」的情况。

## 5. 排错

| 现象 | 原因 / 怎么办 |
|---|---|
| 打开 `.user.js` 地址没弹安装页 | 用 `file://` 打开不会触发安装，必须走 http(s) |
| 界面显示「检查更新失败」 | 看 §4 的两个硬性要求；本仓库发版时两个资产是一起挂的，不会漏 |
| 一直显示「已是最新版本」 | 同上：没有显式声明 `@updateURL` 时，ScriptCat 推算出来的 meta.js 地址会 404，于是静默失败 |
| 面板一直打橙色告警 | 你用的是 Tampermonkey 不是 ScriptCat，见 §1 |
| 题干/选项是乱码 | 字体解密没生效。脚本自带的映射表与基线由构建闸门校验；若改过 `src/assets/font-table-2.0.json` 必须重跑 `pwsh -File src\build.ps1` |
| 章节测验一直不提交 | 正确率没到门槛（默认 80%）。填空题尚未实现，会被跳过并计入分母，详见 README 的「已知未验证」 |
| 脚本卡住不动 | v1.8 之前是翻章模式存储污染导致的，当前版本已修。若仍复现，用调试通道 `curl -X POST http://127.0.0.1:8124/__cmd -d '{"cmd":"status"}'` 看状态 |
| 版本号带 `-AI`、点「检查更新」永远没反应 | 你装的是**调试变体**（`@updateURL` 指向 `127.0.0.1:8124`）。本机服务没开就没有更新源；换回正式版见 §3 末尾那段 |
