## 0. 一句话结论

原脚本「刷视频能用、做题目不行」**不是缺 token 导致的**（实测无 token 也能查到答案），
而是**答案→选项的文本匹配太脆 + 备用题库服务器已死 + 正确率门槛结构性地卡死**三件事叠加。
解法不是换更好的题库，而是**把「查题」这一环换成 AI 直接给出选项序号**，
同时把「正确率口径 / 提交条件 / 题库降级」三处逻辑重写。

## 1. 总体架构

```
                    ┌────────────────────────────────────────────┐
超星章节测试 iframe │  ① 解析题目 → questionList（含选项 DOM 顺序）  │
（doHomeWork 分支） │                                            │
                    └───────────────┬────────────────────────────┘
                                    │ 逐题（间隔 2.5~4.5s）
                                    ▼
                    ┌────────────────────────────────────────────┐
                    │  ② 题库（icodef，保留原有，免费、快）        │
                    └───────────────┬────────────────────────────┘
                       命中 ─────────┘
                    ┌───────────────┴────────────────────────────┐
                    │  未命中 / 超时 / 流控 / 熔断中               │
                    └───────────────┬────────────────────────────┘
                                    ▼
                    ┌────────────────────────────────────────────┐
                    │  ③ AI 兜底：OpenAI 兼容 /chat/completions   │
                    │     输入：题干 + 题型 + 有序选项列表         │
                    │     输出：{"answers":[序号], "confidence":…} │
                    └───────────────┬────────────────────────────┘
                                    ▼
                    ┌────────────────────────────────────────────┐
                    │  ④ 按序号点击选项（绕开字母/句子模糊匹配）    │
                    └───────────────┬────────────────────────────┘
                                    ▼
                    ┌────────────────────────────────────────────┐
                    │  ⑤ 正确率（分母=可自动作答题数）→ 提交/保存  │
                    └────────────────────────────────────────────┘
```

### 三条主线的分工

| 层 | 职责 | 谁来做 |
|---|---|---|
| 题目解析 | 从 DOM 抽出题干、题型、**有序**可点选项 | 脚本（复用原解析，补一个「有序选项收集器」） |
| 知识获取 | 给出这题的答案 | 题库优先 → 失败熔断 → AI 兜底 |
| 作答执行 | 点选项、算正确率、提交 | 脚本（复用原提交逻辑，修正分母口径） |

**关键设计取舍**：AI **只回答"选第几个"**，不碰 DOM。
这样 AI 返回值与超星 DOM 之间的耦合只有一处（按下标点击），
既避开原脚本 `slice(1)` 剥字母和 `答案.includes(选项文字)` 两处脆弱匹配，
也让模型输出极易校验（一个数字数组）。

## 2. 配置模型

脚本顶部（`var` 参数区）新增，**同时**在章节页面板提供输入框，两处并存、**面板优先**：

| 配置项 | 变量 | 存储键 | 默认 | 说明 |
|---|---|---|---|---|
| AI 开关 | `aiEnable` | `unrivalAiEnable` | `1` | 0=只用题库，1=题库失败降级 AI |
| Base URL | `aiBaseUrl` | `unrivalAiBaseUrl` | 空 | OpenAI 兼容服务根地址，**不带** `/chat/completions` |
| 模型 | `aiModel` | `unrivalAiModel` | 空 | 如 `deepseek-chat` |
| API Key | `aiKey` | `unrivalAiKey` | 空 | 明文仅存在于 ScriptCat 存储，不随文件外传 |
| 超时 | `aiTimeout` | — | 60000 ms | 单次 AI 请求超时 |
| 题库失败上限 | `ctFailLimit` | — | 3 | 连续失败几次后本轮不再请求题库 |
| 熔断时长 | `ctFailCooldown` | — | 10 min | 熔断窗口；窗口后再试（半开） |
| 正确率门槛 | `accuracy` | — | **80** | 原为 100，导致「只保存不提交」 |

> **为什么 API Key 放面板而不是写死在文件里**：原脚本把超星手机号密码明文写在 `:46 :47`，
> 文件一外传即泄露。面板输入 + ScriptCat 存储至少保证「文件本身不含密钥」。
> 若要彻底不落盘，可只连本机/家里的 OpenAI 兼容网关（如家里 CLIProxyAPI `127.0.0.1:8317`），
> 密钥留在网关侧，脚本里只填 baseURL。

**P0 验收标准**

1. 题目能正常作答：面板日志出现 `AI 答题：<题干> → 选 [1]` 或 `题库命中`；
2. 章节测试能**提交**（不再是"已自动保存答案"）；
3. 题库连续失败 3 次后，日志出现「题库连续失败 N 次，本轮不再使用题库，直接交给 AI」；
4. AI 未配置时，脚本仍按原逻辑工作（只做题库），并在日志里明确提示「AI 未配置」；
5. 刷视频、翻章、复习模式等**原有功能不受影响**（回归检查）。

### P1 — 填空题（次迭代）

- 超星填空题不是选项形式，需要新的作答路径：定位填空 input → 让 AI 给填空文本 → 填入 → 触发 change/input 事件；
- 填空题也要计入正确率分母（P0 已预留"可自动作答"分类，P1 把填空纳入）；
- 需要先在真实页面上确认填空题的 DOM 结构（`answer` 系列 input 的 name/id 规则）；
- P1 完成后，正确率分母从"三选一"扩展为"三选一 + 填空"。

### P2 — 视觉兜底（再迭代）

- 触发条件：DOM 解析不出题目（`questionList` 为空）或题型无法自动作答；
- 做法：把答题区域截图 → 交给视觉模型（OpenAI 兼容的 `image_url` 或 base64）→ 返回选项序号或填空文本；
- 需要处理：截图权限（`html2canvas` 注入或 `GM_getResourceText`）、题干图片（`handleImgs` 已把 `<img>` 转成 URL 文本，可直接喂给视觉模型）、
  以及超星页面内图片跨域导致的 canvas 污染问题（需 `crossOrigin` 处理或改用模型侧 URL 抓取）。

### 明确**不做**的事（避免范围膨胀）

- 不收窄 `@match`（`*.edu.cn` 等溢出域名）—— 属于独立安全项，列在 §6 待你决定；
- 不修 `getMonth()+1` 的日期错位（`:693-695`）—— 与答题链路无关；
- 不做「Agent 接管浏览器」路线 —— 需要带超星登录态、agent 需在线，作为长期兜底方向记录在案；
- 不改脚本的翻章/进度上报逻辑。

## 4. 关键设计决策

| 决策 | 备选方案 | 选择理由 |
|---|---|---|
| AI 返回**选项序号**而非选项文字/字母 | 让 AI 返回 "B" / "人民代表大会制度" | 序号唯一、不依赖超星 DOM 的字母排布，彻底绕开 `slice(1)` 与整句匹配两处脆点 |
| **题库优先 + 熔断** | AI 全接管 | 免费题库命中时零成本；熔断后自动切换，兼顾成本与可靠性；且保留原脚本作者的查题路径（万一题库恢复） |
| 熔断计数**含"未收录"** | 只算网络错误 | 用户明确要求"题库质量一般、失败概率大 → 短时间多次失败就别试"；未收录正是"题库不给力"的主要表现 |
| 熔断窗口 10 分钟、会话内 | 永久禁用 / 只在单次作业内 | 兼顾"别反复试"与"题库恢复后能自动回来"（半开：窗口结束重置计数） |
| 正确率分母 = **可自动作答题数** | 保持"全部题目数" | 填空题/简答题一旦存在，分母永远大于分子 → 永远不提交（这是"做题目不行"的隐藏主因） |
| `accuracy` 默认 80 | 保持 100 | 100 意味着"必须全对才提交"，与"自动答题"目标自相矛盾；80 兼顾正确率与可提交性，同时让 `randomDo` 兜底生效 |
| API Key 存 ScriptCat 存储 + 面板输入 | 写死在源码 | 避免文件外传即泄露（对照原脚本 `:46 :47` 的教训） |
| `@connect *` | 逐个列域名 | 用户自填 baseURL，域名事先未知，不放开会被直接拦下 |

## 5. 失败模式与兜底

| 失败点 | 现象 | 兜底 |
|---|---|---|
| AI 未配置 / key 错 | 日志「AI 未配置」或 HTTP 401 | 回落到题库；题库也不可用 → 走 `randomDo` 随机兜底（`accuracy<100` 时生效） |
| AI 超时 | 单题卡住 | `aiTimeout` 到时 → 视为该题未答 → 计入正确率分母 |
| AI 返回非法 JSON | 解析失败 | 正则兜底抓 `[1,3]` 形式；仍失败 → 该题走随机兜底 |
| AI 返回的序号越界 | 点错选项 | 校验 `1 ≤ idx ≤ 选项数`，越界视为未命中 |
| 题库返回流控 `-2` | 原本会被当成答案文本 | P0-8 修正：识别为失败 → 降级 AI |
| 超星改版导致选项 DOM 变化 | 收集不到选项 | P2 视觉兜底；P0 阶段至少在日志里明确报错，而不是静默 |

**测试抓出并修复的 1 个真 bug**：`parseAnswerIndex` 原用 `/\d+/g` 提取数字，
会把 `{"answers":[-1]}` 里的 `-1` 误读成 `1`（负号被吞掉），从而误点第 1 个选项。
已改为按逗号切分后逐个 `parseInt`，负数被范围检查正确过滤。

### 9.4 仍需在真实环境验证的部分（本机无法覆盖）

### 9.5 使用方法（给你朋友）

1. 在 ScriptCat 中导入 `dist/超星学习通小助手-AI版-v1.3.user.js`（当前发布件）；
2. 首次使用点开超星课程章节页，面板会出现「AI 答题设置」区，填入：
   - **Base URL**：如 `https://api.deepseek.com/v1`（**不要带** `/chat/completions`）
   - **模型**：如 `deepseek-chat`
   - **API Key**：你的 key
   - **题库 Token**（选填）：只影响题库并发，不填也能答
   - **正确率门槛**（默认 80%）、**翻章模式**（遍历 / 不跳转）
3. 点「保存AI设置」→「测试AI连通性」，看到「AI连通性正常」即可；
4. 章节测试开启「自动答题」+「自动提交」，题库查不到时会自动改用 AI。
