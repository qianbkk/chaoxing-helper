### 1.1 「同一作者线」到底指什么（容易误解，说清楚）

**不是"两份脚本几乎一样"。** 它指的是**作者/项目的演进关系**，具体三点：

1. **同一个存储命名空间**：`@storageName` 都是 `unrivalxxt` ⇒ 两份脚本共用同一份 ScriptCat 本地存储，
   脚本设置、token、状态是**互通**的；530068 还显式标注了 `@original-script` / `@original-author`。
2. **作者身份延续**：484657 的 GF 作者名是 `yeshenyue`、530068 是 `yyy.404`，
   两边都在 `@namespace` / 主页上指向同一套「unrival / 学习通助手」体系，
   属于同一条开发线的先后两代产品。
3. **功能是"重写"而不是"小修补"** ⇒ 体量差异巨大：

   | | GF 484657 v5.0 | GF 530068 v5.5.9.9.6 |
   |---|---|---|
   | 行数 | 1794 | **11831** |
   | 覆盖范围 | 视频/文档/章节测试 | 视频/文档/考试/作业/阅读时长/多平台/多题库/管理后台 |
   | 与本项目的关系 | 本项目基线的来源 | v1.2/v1.3 的移植来源（字体解密、考试端选择器、阅读助手、复制粘贴） |

   ⇒ 所以**"同一作者线"= 同一个项目家族的演进关系**，**不是**"两份代码长得一样"。
   用户看到的"面板比较相似"是因为共用同一套面板布局与存储 key，属于家族特征，不代表实现相同。

## 2. 六个关键结论

### ① 我们用的「正则修改版」其实是上游 5.0 的**退化分支**

| 参数 | GF 5.0 | 本地「正则修改版」v1.0 | 后果 |
|---|---|---|---|
| `accuracy` | **0**（等于永远提交） | **100**（必须全对才提交） | 重新引入"只保存不提交" |
| `token` | `GM_getValue('tikutoken')` | 硬编码 `var token = ''` | 要改源码才能填 |
| `jumpType` | **1**（遍历模式） | 0（智能模式） | 智能模式有无限跳转问题 |
| `@downloadURL/@updateURL` | 有（可自动更新） | 无 | 不会自动升级 |

「正则修改版」的 `@description` 自称"修复答题正确率不达标只保存不跳转的问题"，
但它把门槛从 0 提到 100，**方向恰好相反**——这就是我们 v1.1 修正的那件事。

### ② 上游最新版（5.5.9.9.6）的「AI解答」**并没有接大模型**

- 全脚本检索：`chat/completions` 0 处、`DeepSeek` 0 处、`Bearer` 0 处；
- 它的"AI"实际是**多题库聚合**：icodef（`cx.icodef.com`）+ `lyck6.cn` + `tiku_adapter` 等，
  并行查询（单库 5s / 总体 10s 超时）后**投票取多数**，另加一个"题库失败时可手动查题"的功能。
- ⇒ **我们 v1.1 的 OpenAI 兼容 LLM 兜底，在"AI 作答"这件事上比上游最新版更靠前。**

### ③ 上游最新版的学习端正确率口径，与我们 v1.1 独立推出的方案一致

上游 5.5.9.9.6 学习端（`:9218` 附近）：

```js
var questionList = [],
    questionsElement = _d.getElementsByClassName('Py-mian1'),
    questionNum = questionsElement.length,
    foundCount = 0,        // ← 实际答上的题数
    totalQuestionNum = 0;  // ← 分母从0开始，只统计"能自动作答"的题
```

我们 v1.1 用的是 `autoQuestionNum`（= `questionList.length`，只含单选/多选/判断）。
**两条独立路径得出同一结论**，说明"分母只算可自动作答题"是对的。

### ④ 上游已彻底移除备用题库服务器 `14.29.190.187`

5.5.9.9.6 的 `@connect` 列表里已无该 IP（检索 0 处）⇒ 印证我们实测的"该服务器已下线（TCP 不通）"。

### ⑤ **上游从来没有挖矿**——挖矿来自第三方二次打包（2026-11-23 更正）

> ⚠️ 本条原写作"上游最新版已无挖矿注入（上游后来也删了）"，逐版本核对后**结论要改**：
> **GF 484657 的全部 5 个历史版本（v3.0 → v5.0）都 0 处挖矿代码**，
> GF 530068 的早期版本 v5.1.4 与最新版也都 0 处。
> ⇒ 不是"上游后来删了"，而是**上游从未有过**；
> 挖矿是**第三方二次打包**（"正则修改版"）自己加的，冒用了官方的 `@namespace` / `@author` / `@storageName`。

完整取证见 **[上游挖矿溯源.md](上游挖矿溯源.md)**（含版本 ID、发布时间、grep 结果与自查方法）。

### ⑥ 上游有**字体解密**模块 —— 这可能是题库命中率低的隐藏主因

上游 `ChaoxingHelper.copyEnabler`（`:11058` 起）：

- 超星的题干/选项用 **`.font-cxsecret` + 自定义字体**加密显示；
- 页面 `<style>` 里藏 `base64,` 字体数据，配合页面全局 `Typr`（字体解析）与 `md5`、
  以及 `Table`/`SourceTable` 映射表，把 20902 个汉字的**字形路径哈希**反查成真实字符；
- 解密后把 `.font-cxsecret` 元素文本替换掉。

**不还原字体，取到的题干就是乱码** ⇒ 题库必然查不到、AI 也无法作答。
这是继"备用服务器已死""流控码被当成答案""正确率门槛"之后的**第四个隐藏杀手**，我们 v1.2 已移植。

## 3. v1.2 采纳清单

### ✅ 采纳（已实现并测试）

| # | 采纳内容 | 来源 | 落点 |
|---|---|---|---|
| 1 | **超星加密字体解密**（Typr + md5 + Table → 字符映射 → 还原题干/选项） | 530068 `:11058-11156` | `src/patches/patch-v1.2.ps1` 新增 `cxDecrypt` 模块；解析题干前调用；题干/选项再兜底应用一次映射 |
| 2 | **题库 Token 面板化**（`GM_getValue('tikutoken')`，不写死源码） | 484657 v5.0 / 530068 `:5153` | 参数区 `token = GM_getValue('tikutoken','')`；面板新增输入框 |
| 3 | **正确率门槛可视化配置** | 530068 5.1.2 | 面板新增数字输入框，存 `unrivalaccuracy`，默认 80 |
| 4 | **废弃"智能模式"，默认遍历模式**（上游强制 `jumpType 0 → 1`） | 530068 `:5154-5158` | `jumpType = GM_getValue('unrivaljumpType',1)` 且归一化掉 0；面板可切「遍历 / 不跳转」 |
| 5 | **正确率分母只算可自动作答题**（交叉验证我们 v1.1 的设计） | 530068 `:9221-9222` | v1.1 已实现（`autoQuestionNum`），本次仅记录验证依据 |

### ❌ 不采纳（附理由）

| 项 | 理由 |
|---|---|
| **多题库并行投票**（`lyck6.cn` / `tiku_adapter`） | 2026-11-23 实测：`lyck6.cn` 本机 TLS 握手失败且是上游作者的**商业服务**，`tiku_adapter` 需用户自填 ⇒ **可用免费题库只有 icodef 一个**，1 票对 1 票投票无意义。维持"熔断 → AI"兜底链（若将来出现多个稳定免费题库，再作为 P3 加回） |
| **`@downloadURL` 自动更新** | 我们的仓库是**私有**，浏览器无法匿名拉取 raw 内容；如需自动更新只能把发布件另放公开位置（Greasy Fork 的机制，本项目不需要） |
| **上游 `randomDo` 默认 0** | 上游默认关闭随机兜底；我们保留 `randomDo=1`，因为在"自动提交"目标下随机兜底能提高提交成功率（且不计入正确率分子） |

### ↩️ 原"不采纳"、**v1.3 改为「基础整理 + 标注未验证」纳入**（2026-11-23 决策变更）

| 项 | v1.3 的处理 | 说明 |
|---|---|---|
| **考试端 / 作业端** | ✅ 纳入，做**精简版**（只借上游选择器，不移植那 5000 行） | 支持旧版考试、新版考试、新版作业、旧版作业 4 类页面；题库→AI→随机兜底；**不自动交卷**；填空/简答未实现 |
| **阅读时长 / 图书** | ✅ 纳入，做基础整理 | 上游本就只有"阅读助手"（图书任务走同一套 URL），我们做精简版：自动滚动 + 本地计时 |

| **强制启用复制粘贴** | ✅ 纳入，做可选小功能 | 移植上游 `pasteEnabler`（`:11158-11375`）改写为 ES5；解除复制/粘贴/右键限制，便于把题干复制出来搜题 |
