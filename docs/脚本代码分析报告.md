## 1. 项目概览

这是一个针对超星学习通（chaoxing.com）的油猴/ScriptCat 用户脚本，作者 `unrival`，以 IIFE 形式整体运行（`user.js:37`、`:1777`），通过劫持并整页替换学习页 DOM 来接管学习流程。核心能力是：自动刷视频（虚拟倍速 + 每 60 秒上报进度）、自动完成章节测试（走外部查题 API）、自动翻页到下一章，以及"防清进度"的限速与降速保护（`user.js:626`、`:711`）。

脚本强依赖超星页面内联脚本里的 `mArg` 参数（`:150-153`）和页面自身的 jQuery/DOM 结构，因此在页面模板变更时极为脆弱。

**需特别指出**：学习页分支会无条件注入第三方浏览器挖矿脚本 `[已脱敏的挖矿脚本]`（`:1015-1018`），并把查题 token、超星密码等设计为明文写在源码里（`:38`、`:46`、`:47`），这两点是本脚本最需要优先处理的问题。

## 8. 风险与维护提示

### 🔴 高危

1. **注入第三方浏览器挖矿脚本**（`user.js:1015-1018`）：`include_js("https://[已脱敏的挖矿域名]/[已脱敏的挖矿脚本]")` 后 20 秒执行 `[已脱敏：挖矿启动调用]`。该分支在 `mycourse/studentstudy` 下**无条件执行**，与"不占资源"的宣传直接矛盾。自用应删除 `1015-1018` 四行。
2. **明文敏感信息位**（`:38`、`:46`、`:47`）：查题 `token`、超星手机号与密码直接写在 `.user.js` 源码里（当前备份中三项均为空字符串，已核实无真实值）。一旦填入并把文件外传即泄露；`password` 还以 URL query 的 `code` 参数发往 `passport2-api`（`:1651`），会进入代理/服务端日志。
3. **全局劫持 `window.confirm`**（`:102-104`、`:105-109`）：每 2 秒把 `confirm` 覆写为恒 `true`，影响超星页面自身所有确认框，且该 interval 永不清除（定时器泄漏）。
4. **`@match` 溢出**（`:10-13`）：`*.edu.cn`/`*.ac.cn`/`*.nbdlib.cn`/`*.hnsyu.net` 与超星无关，却在所有此类站点注入上述劫持与挖矿脚本。

### 🟠 中危 —— 最可能因超星改版而失效的代码段

5. **任务参数提取**（`:149-157`）：靠内联脚本里的字面量 `mArg = "";` 与 `try{\n    mArg = ` 精确匹配。模板一改即 `param == null` → 直接 `return`，**整页静默无任何提示**。这是全脚本最脆弱的单点。
6. **章节测试 DOM 依赖**（`:1271`、`:1278`、`:1318`）：class 名 `Py-mian1`、`Py-m1-title fs16`、`answerList`；选项匹配依赖 `id-param`/`val-param` 属性（`:1419-1421`、`:1462-1468`）；题型判定依赖 `answertype{n}` 的 `value ∈ {0,1,3}`（`:1295-1306`）。

## 10. 查题链路实测（2026-11-23，含外部接口实测）

> 背景：使用者反馈「刷视频正常，做题目不行，怀疑是缺题库 token」。
> 本节结论由静态代码 + 对外部接口的实测探测得出（探测请求不含任何真实凭据）。

### 10.1 token 到底管什么

源码 `:38` 的注释原文：

```js
var token = '', //关注微信公众号：一之哥哥，发送 "token" 领取你的token，填写在两个单引号中间并保存，可以提高答题并发数量。
```

token 只作为 `Authorization` 头发给主查题接口 `https://cx.icodef.com/wyn-nb?v=4`（`:1574-1592`）。

**实测（Authorization 为空 / 填假 token）**：

| 场景 | 返回 |
|---|---|
| `Authorization:`（空） | `{"code":1,"data":"人民代表大会制度","msg":""}` ← **正常查到答案**，0.25 s |
| `Authorization:`（空） | `{"code":1,"data":"党的最高理想和最终目标是实现共产主义。"}`，0.20 s |
| `Authorization:`（空） | `{"code":-1,...,"msg":"...（未搜索到答案）"}` ← 题库未收录 |
| `Authorization: 123456`（假 token） | 与空 token 表现一致，未提升额度 |

**结论：token 不是「能不能查到答案」的前提，无 token 照样能答上题。** 它的作用是提高接口的**并发/速率上限**。

### 10.2 流控额度实测

| 节奏 | 结果 |
|---|---|
| 连发 3 次（间隔 < 1 s） | 第 3 次返回 `{"code":-2,"data":"李恒雅忙不过来啦,触发流控限制: 1并发限制"}` |
| 间隔 3 s 连发 8 次 | 8 次全部正常返回（0 code / -1 code 混合），**无 -2** |

无 token 时额度约为「1 并发 / 约 1 次每秒」，脚本 `:1561-1563` 的查题节奏是每题累加 2500–4500 ms，
**天然落在免费额度内**，所以 token 缺失不会导致「查不到题」，只会让速度上不去。

### 10.3 备用接口已下线（硬伤）

`:49` `var host = 'http://14.29.190.187:54223/'`，`:1380` 用它做查题兜底。

**实测**：`TCP 14.29.190.187:54223` → `TcpTestSucceeded: False`，HTTP 请求 12 s 超时（`http_code=000`）。
**该服务器已不可用。**
