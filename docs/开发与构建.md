## 题库链路（v1.11.3 起）

题库不再是「一条路 + 首个包含即命中」，而是**多源客户端 + 打分匹配**。
实现在 `src/modules/ctbank.v1.11.3.js`（活源码，由 `patch-v1.11.3.ps1` 整段注入），
作业端 / 考试端 / 学习端三处调用点都走它。

### 三个免费源

| 源 | 地址 | 密钥 | 角色 | 实测（2026-11-25） |
|---|---|---|---|---|
| icodef | `https://cx.icodef.com/wyn-nb?v=4` | 不需要（token 选填） | 主源（并行） | 匿名 `code:1` 可用；**间隔 <1.5 秒必被限流**（`code:-2`） |
| 百度不挂科 | `https://easylearn.baidu.com/edu-web-go/bgk/searchlist` | 不需要 | 主源（并行） | 零密钥；返回体是 XOR 加密的 JSON，需解密后取 `que_options[0]` 里 `yes=true` 的选项文字 |
| icodef 备用 | `https://q.icodef.com/wyn-nb?v=4` | 不需要 | **兜底**（主源全败后才试） | 与主源**共享 IP 每日限额**，本机返回「触发流控限制: IP超出每日限额」→ 并行去查会白白吃掉主源额度，所以降级成备用 |

### 失败分类（关键：区分「没这道题」和「服务坏了」）

| 情况 | 判据 | 处理 |
|---|---|---|
| 未收录 | icodef `code:-1`；百度题干相似度低于 0.70 | **不算失败**，不熔断，记一条日志后转交 AI |
| 流控 | icodef `code:-2` | **退避重试**（2.5 秒 / 6 秒，最多 2 次），不算失败、不熔断 |
| 网络错误 / 超时 | `onerror` / `ontimeout` | **计入熔断**：连续 3 次 → 熔断 10 分钟（状态跨翻章持久化） |

> v1.11.2 之前把「未收录」和「流控」都算失败 —— 题库里没有这道题是很正常的事，
> 3 道没收录的题就能把题库整个关掉 10 分钟。这是本次改造的主要动机之一。

### 匹配规则

- 答案 → 选项**打分制**，不再「首个包含即命中」：
  完全相等 1.0 / 答案句包含选项文字 `0.70+0.25×占比` / 选项包含答案 `0.62+0.20×占比` /
  其余走二元组 Dice 相似度 × 0.8；**低于 0.62 不算命中**。
- **单选题只取最高分那一个**（修掉「一句话勾多个」）；**多选题**把 `#` 分隔的多条答案陈述分别映射后取并集。
- **判断题走同义表**（正确/对/√/是/true ↔ 错误/错/×/否/false）。
- **否定词防护**：「不正确」既不命中「正确」也不命中「错误」；极性冲突一律不算命中。
- 百度源返回的是**正确选项的文字**（不是字母）—— 超星会打乱选项顺序，返回字母会答错。

## 补丁链约定

补丁脚本用**字符串锚点**替换，每处替换前断言锚点**恰好命中指定次数**：

```powershell
function Replace-Once([string]$t, [string]$old, [string]$new, [string]$label) {
    $count = ([regex]::Matches($t, [regex]::Escape($old))).Count
    if ($count -ne 1) { throw "锚点[$label] 命中 $count 次（应为 1 次）" }
    return $t.Replace($old, $new)
}
```

整块替换（注入模块）用「起始标记 / 结束标记」区间定位 ——
模块内部被改过之后，全文匹配会失效：

```powershell
function Replace-Region([string]$t, [string]$beginMark, [string]$endMark, [string]$new, [string]$label) { ... }
```

模块源码放在 `src/modules/xxx.vX.Y.js`，由补丁整段注入脚本本体。

### 面板栅格：桌面端不许换行（v1.11.4 起）

面板左右两栏的容器是：

```css
.unrival-mainrow { display:flex; flex-wrap:nowrap; align-items:flex-start; margin:0 -8px; }
.unrival-maincol { flex:1 1 520px; min-width:0; margin:0 8px; }
.unrival-sidecol { flex:0 0 250px; margin:0 8px; position:sticky; top:12px; }
```

**为什么必须是 `nowrap`**：v1.11.2 写的是 `flex-wrap:wrap`。两栏的基准宽度合计
`520 + 250 + 32（左右 margin）= 902px`，而主容器是 `col-md-10`（视口宽的 10/12），
于是**视口窄于约 1082px 时**（1024 笔记本、浏览器放大 110%、DevTools 开着），
右栏会整块换行掉到左栏下面 —— 「开始/继续」就跑到页面最下面了。

**实测（2026-11-25，Chrome，1024×900 视口）**：

| 版本 | 右栏 top | 「任务配置」top | 结论 |
|---|---|---|---|
| v1.11.3（`wrap`） | 1461px | 87px | 掉到页面很下面 |
| v1.11.4（`nowrap`） | 87px | 87px | 与「任务配置」齐平，紧挨其右方 |

窄屏（≤991px）仍然允许换行，并用 `order:-1` 把右栏顶到最上面 —— 那是刻意的，
手机上也别把主操作按钮压在下面。

## 两种发布变体

| 变体 | 位置 | 更新地址 | 用途 |
|---|---|---|---|
| 正式版 | `dist/chaoxing-helper.user.js` | **jsDelivr**（读 `main` 分支的 `dist/`） | 别人装的就是它 |
| 调试变体 | `build/chaoxing-helper.debug.user.js` | `127.0.0.1:8124` | 本机自用：接收端发现新版本 → 脚本自动弹安装页 |

两者**只差两行元数据**（`@updateURL` / `@downloadURL`），由同一个补丁用不同参数生成，不会漂移。
`tests/release-meta.test.js` 里有一条断言就是「除更新地址外两者完全一致」。

> **为什么正式版走 jsDelivr（v1.11.5 起）**：「检查更新」是浏览器直接请求 `@updateURL`，
> GitHub 在国内快慢极不稳定（实测 715KB 的文件三轮里两轮 30 秒超时下载不全），
> 而 `cdn.jsdelivr.net` 国内可直连（三轮全 200，字节与 `dist/` 一致）。
> 代价是它有**几分钟到几十分钟的缓存延迟**，不是提交即到。
> **GitHub Releases 照常发版**，作为 jsDelivr 走不通时的备用通道。

## 发布流程

```powershell
# 1. 重建 + 全测
pwsh -File src\build.ps1
Get-ChildItem tests\*.test.js | ForEach-Object { node $_.FullName }

# 2. 发布卫生闸门（会复查：地址、版本、挖矿残留、他人邮箱、硬编码密钥、赞赏码）
node tests\release-meta.test.js

# 2b. 文档链接自检（相对链接是否都指向真实存在的文件）
node src\tools\check-links.cjs

# 3. 提交并推送（推完 main，jsDelivr 才能取到新版；缓存刷新要几分钟）
git add -A
git commit -m "feat(vX.Y.Z): ……"
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main

# 4. 发 Release（备用通道，两个资产一起挂）
gh release create vX.Y.Z --title "vX.Y.Z" --notes "……" `
    dist\chaoxing-helper.user.js dist\chaoxing-helper.meta.js
```

发完之后，已安装的用户点「检查更新」就能拿到新版本 ——
更新检查走 jsDelivr（读 `main` 分支的 `dist/`），而 Release 是备用通道。

> ⚠️ **推送顺序**：先推 `main`，再发 Release。
> jsDelivr 读的是 `main` 分支，`dist/` 是提交进仓库的 ——
> `main` 没推上去之前，jsDelivr 上还是旧版本。

## 调试通道能干什么

| 命令 | 作用 |
|---|---|
| `pause` / `resume` | 暂停 / 继续（自动翻章、自动作答、自动提交全停） |
| `status` | 把当前状态写进日志（版本/章节/暂停/翻章模式/AI 配置/熔断/正确率门槛） |
| `reload` | 刷新当前页面 |
| `goto <chapterId>` | 跳到指定章节 |
| `set <key> <val>` | 改设置：`accuracy` / `jumpType` / `ctFailLimit` / `ctFailCooldown` / `aiModel` / `aiBaseUrl` |
| `log <text>` | 往日志里插一行（打标记用） |
| `dump` | 导出当前章节的任务清单、附件属性、阅读/直播链接、iframe、missionList（研究用） |
| `help` | 列出命令 |

## 实测：超星页面形态与脚本的对应关系（2026-11-25）

在真实超星页（课程 `courseId=268157391`、章节 `chapterId=1266095428`，
西安航空学院网络教学平台）用 `dump` 探到的结构：

| 页面 | URL 形态 | 脚本里的角色 |
|---|---|---|
| 章节外壳页 | `/mooc-ans/mycourse/studentstudy?chapterId=…&courseId=…&clazzid=…&enc=…` | 顶层页面；`enc` 参数丢了会被打回登录页 |
| 章节任务卡片 | `/mooc-ans/knowledge/cards?clazzid=…&courseid=…&knowledgeid=<chapterId>…`（嵌在上面那个页面的 iframe 里） | **脚本面板挂在这里**；`autoRun` 看门狗也只在这个页面启动（判据是 `href` 含 `knowledge/cards`） |
| 阅读任务 | 卡片页 `attachments` 里的一条：`type=read`、`jobid=read-<数字>`、`name=《…》`、`property` 含 `read/jobid/_jobid/module/mid` | 阅读任务的**元数据**在这一层 |

由此得到三条：

1. **命令要在对的那个上下文里执行**。顶层外壳页的 `dump` 拿不到任务清单
   （`param` 未定义 → 「attachments 解析失败」），要拿清单得看**卡片页**那个上下文。
2. **⚠️ 未验证 —— 阅读正文页能不能命中**。`readAssist.isReadingPage()` 只认
   `/ztnodedetailcontroller/visitnodedetail`；而这套超星把阅读任务挂在
   `knowledge/cards` 卡片页上（附件 `type=read`）。**点开阅读附件后落地的是哪种 URL，
   本次没能确认**（超星会话失效，页面被打回登录）。所以「阅读助手在这套超星上会不会启动」
   仍是未验证，README 与安装文档里保持「未验证」标注。
3. **任务点已过也能读**这件事与超星的判定口径一致：阅读任务按**真实浏览时长**判定，
   任务点亮了也照样要读满时长，脚本只负责把内容滚过去。

## 调试通道的三个使用坑（2026-11-25 实测）

| 坑 | 现象 | 怎么办 |
|---|---|---|
| 命令在**所有页面上下文**里各执行一次 | `reload` 会把顶层页 + 每个 iframe 一起刷新 | 想只刷一个页就别用 `reload`；用地址栏导航 |
| 后台标签页里轮询被浏览器降频 | 命令投下去几秒没回音，日志也停 | 先把那个标签页点到前台，轮询立刻恢复（实测后台标签约 1 分钟才回一次） |
| 超星会话会失效 | 页面变成「用户未登录」，跳 `passport2.chaoxing.com/login` | 浏览器保存的密码提交后不生效，得走**验证码登录**（点选图形验证 → 短信码）；`refer` 要带原章节 URL 的 `enc` 参数才能跳回去 |

> 顺带记录一条调试工具的用法：本机是 200% DPI 屏，**截图文件本身是物理像素（2560×1600），
> aardio 的鼠标坐标也是物理像素** —— 两边同一套坐标，可以直接对着截图上的位置点。
> 唯一要小心的是「看图的那一步」：本会话里图片预览会被缩到 2000×1250，
> 读到的位置要乘 1.28 才是原始像素。
> 那次实测里，ScriptCat 安装页的「更新」按钮就在物理坐标约 **(1920, 480)**。
