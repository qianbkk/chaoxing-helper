## 日常流程

```powershell
# 1. 改生成脚本（不要直接改 dist/ 里的发布件）
notepad src\patches\patch-vX.Y.Z.ps1
notepad src\modules\*.js
notepad src\build.ps1

# 2. 重建（会做完整性闸门 + 两个产物的语法校验）
pwsh -File src\build.ps1

# 3. 跑全套测试（十二套，671 项断言）
Get-ChildItem tests\*.test.js | ForEach-Object { node $_.FullName }
```

> 测试全部指向 `dist/chaoxing-helper.user.js` —— 测的就是要发布的那一份。

## 补丁链约定

补丁脚本用**字符串锚点**替换，每处替换前断言锚点**恰好命中指定次数**：

```powershell
function Replace-Once([string]$t, [string]$old, [string]$new, [string]$label) {
    $count = ([regex]::Matches($t, [regex]::Escape($old))).Count
    if ($count -ne 1) { throw "锚点[$label] 命中 $count 次（应为 1 次）" }
    return $t.Replace($old, $new)
}
```

整块替换（注入模块）用「起始标记 / 结束标记」区间定位 ——
模块内部被改过之后，全文匹配会失效：

```powershell
function Replace-Region([string]$t, [string]$beginMark, [string]$endMark, [string]$new, [string]$label) { ... }
```

模块源码放在 `src/modules/xxx.vX.Y.js`，由补丁整段注入脚本本体。

## 构建期闸门

`src/build.ps1` 的第一步是 `tools/verify-baseline-font-table.cjs`：
把**基线里真正内联的那张字形映射表**与 `src/assets/font-table-2.0.json` 逐条比对。

两者失配的后果是**静默**的：脚本里的查表全部落空 ⇒ 字体解密不命中 ⇒
题干和选项全是乱码 ⇒ 题库和 AI 都答不了，而构建过程一声不吭。

手工改过 `src/assets/font-table-2.0.json` 后**必须**重跑构建。

## 两种发布变体

| 变体 | 位置 | 更新地址 | 用途 |
|---|---|---|---|
| 正式版 | `dist/chaoxing-helper.user.js` | GitHub Releases | 别人装的就是它 |
| 调试变体 | `build/chaoxing-helper.debug.user.js` | `127.0.0.1:8124` | 本机自用：接收端发现新版本 → 脚本自动弹安装页 |

两者**只差两行元数据**（`@updateURL` / `@downloadURL`），由同一个补丁用不同参数生成，不会漂移。
`tests/release-meta.test.js` 里有一条断言就是「除更新地址外两者完全一致」。

## 发布流程

```powershell
# 1. 重建 + 全测
pwsh -File src\build.ps1
Get-ChildItem tests\*.test.js | ForEach-Object { node $_.FullName }

# 2. 发布卫生闸门（会复查：地址、版本、挖矿残留、他人邮箱、硬编码密钥）
node tests\release-meta.test.js

# 3. 提交并推送
git add -A
git commit -m "feat(vX.Y.Z): ……"
$env:HTTPS_PROXY='http://127.0.0.1:7897'; $env:HTTP_PROXY='http://127.0.0.1:7897'
git push origin main

# 4. 发 Release（两个资产一起挂，缺一个「检查更新」就会失败）
gh release create vX.Y.Z --title "vX.Y.Z" --notes "……" `
    dist\chaoxing-helper.user.js dist\chaoxing-helper.meta.js
```

发完之后，已安装的用户点「检查更新」就能拿到新版本 ——
`releases/latest` 指向最新 Release，而元数据块里的 `@version` 更高。

## 本机服务

| 服务 | 端口 | 作用 |
|---|---|---|
| `node src/tools/log-sink.cjs` | 8124 | 调试接收端：日志落盘、远程操控、版本自检、提供 `/latest.*` |
| `pwsh -File src/tools/serve-dist.ps1` | 8123 | 发布件服务：安装/更新用，动态提供任意历史版本名的别名 |

```powershell
# 投递命令 / 看日志 / 看状态
curl -X POST http://127.0.0.1:8124/__cmd -H 'Content-Type: application/json' -d '{"cmd":"status"}'
curl 'http://127.0.0.1:8124/__log?tail=100'
curl 'http://127.0.0.1:8124/__status'
```

> ⚠️ 这两个服务是**常驻**的，重启机器后要重新拉起来；
> 别在用户正在用的时候随手关掉。

## 常见任务

| 任务 | 怎么做 |
|---|---|
| 加一个新版本 | [../src/README.md](../src/README.md) §「怎么新增一个版本」 |
| 改面板 UI | 改 `src/modules/layout.vX.Y.js`（折叠、限高），补丁整段注入 |
| 改调试命令 | 改 `src/modules/debugcmd.vX.Y.Z.js`，注意版本标记要同步 |
| 加一个调试命令 | 在 `dbgCmd.exec` 的 `switch` 里加一个 `case`，并在 `help` 里补一行；记得同步 `tests/debugcmd.test.js` |
| 调研直播/阅读页面结构 | 用 `dump` 命令：`curl -X POST http://127.0.0.1:8124/__cmd -d '{"cmd":"dump"}'`，结果写回日志文件 |
| 排查「检查更新失败」 | [安装与自动更新 §5](安装与自动更新.md) 排错表 |
| 确认发布件没夹带敏感信息 | `node tests/release-meta.test.js` |

## 调试通道能干什么

| 命令 | 作用 |
|---|---|
| `pause` / `resume` | 暂停 / 继续（自动翻章、自动作答、自动提交全停） |
| `status` | 把当前状态写进日志（版本/章节/暂停/翻章模式/AI 配置/熔断/正确率门槛） |
| `reload` | 刷新当前页面 |
| `goto <chapterId>` | 跳到指定章节 |
| `set <key> <val>` | 改设置：`accuracy` / `jumpType` / `ctFailLimit` / `ctFailCooldown` / `aiModel` / `aiBaseUrl` |
| `log <text>` | 往日志里插一行（打标记用） |
| `dump` | 导出当前章节的任务清单、附件属性、阅读/直播链接、iframe、missionList（研究用） |
| `help` | 列出命令 |
