## 1. 它做什么

进入超星课程章节页，脚本接管并开始自动学习：

- **自动刷视频与文档**：按课程目录逐个处理任务，记录播放进度，按设定的翻章模式进入下一章。
- **章节测验 / 作业自动作答**：解析题目与选项，**先查免费题库**（v1.11.3 起：**三个免费源一起查**，答案与选项**按相似度打分**匹配，单选只取最像的那一个），三个源都没有才**自动降级到 AI**（任何 OpenAI 兼容接口）。
- **超星加密字体自动解密**：超星把题干和选项用自定义字体加密显示，不解密就是一堆乱码 —— 题库和 AI 都答不了。脚本自带映射表，**不依赖任何外部 CDN**。
- **运行控制**：面板**右上角单独一栏**里两个按钮 ——「**开始/继续**」（绿色大号主按钮）与「**暂停**」（红色小号），自动翻章、自动作答、自动提交全停，状态跨翻章保持。窄屏时右栏会自动顶到最上面。
- **全程托管模式**（**默认关闭**）：遇到直播 / 阅读这类脚本做不了的任务时**跳过并记账**，继续往下推进，直到没有下一节为止 —— 不用守着看它停下来。
- **阅读助手**（**默认关闭**）：打开阅读正文页后自动逐段滚着读完 —— **每段默认停 10 秒**，而且会一路读到**页面加载不出新内容为止**（往下滚才出现的后半篇也读）（超星按真实浏览时长判定，所以读多久就是多久，不能秒过）。
- **调试模式**（**默认关闭**）：面板日志实时落盘到本机文件，并支持从命令行远程操控脚本。
- **面板**：所有配置都在页面上的一个面板里，不用改脚本文件。左边配置、右边运行控制，小块左右并排，调试相关的东西在最下面。
- **运行日志**：统一成 `[时间] [标签] 句子` 的格式（标签分 12 类：视频 / 文档 / 测验 / 答题 / 题库 / AI / 阅读 / 托管 / 翻章 / 运行 / 设置 / 系统），重复消息自动合并成 `（×N）`，开发自检信息只进调试通道、不进用户日志。

### 三条主线之外的能力边界

写清楚是为了不让人误以为「装上就什么都能干」：

| 能力 | 状态 |
|---|---|
| 章节测验 / 作业自动作答 | ✅ 完整链路已在真实超星页跑通（题库 → AI → 自动提交 → 任务点亮）；v1.11.3 换成多源题库 + 打分匹配后，**接口层已用真实接口端到端复验**（两个源各自独立答对 4/5），⚠️ **但整条页面链路未在真实超星页复验**（当时会话已失效） |
| 加密字体解密 | ✅ 已在真实页实测（168 字符逐字命中 40/40） |
| 阅读任务点 | ⚠️ **v1.11.2 起阅读助手**（默认关闭）：打开阅读正文页后按「每段 N 秒」（默认 10 秒）**把整篇读完**，往下滚才加载出来的后续内容也读到加载不出来为止。⚠️ **未在真实超星页复验**（测试时该任务已过期），页面结构对不上时会记录「没找到正文内容」并放弃 |
| 直播任务点 | ❌ **未实现**，整条技术线都没有。默认会打出任务类型并停下提示人工处理；开「全程托管」则**跳过继续**（该节任务点不会亮） |
| 全程托管模式 | ⚠️ v1.11.0 新增，代码与单测都在，**未在真实超星页复验**；默认关闭 |
| 填空题 | ❌ **未实现**，会被跳过 |
| 复制粘贴 / 考试端作答 / 任务页保活 | ⚠️ 代码与单测都在，但**真实页面未验证**，默认全部关闭 |
| 截图交视觉模型兜底 | ❌ 未实现 |

> 为什么直播和阅读做不了、查过哪些线索，见 [docs/来源与安全说明.md](docs/来源与安全说明.md) 与
> [docs/v1.4章节测验与字体解密说明.md](docs/v1.4章节测验与字体解密说明.md)。

## 2. 安装

### 2.1 先装 ScriptCat（脚本猫）

脚本是给 **ScriptCat** 写的，里面有一行自检：

```js
isCat = GM_info.scriptHandler == 'ScriptCat';
```

在 Tampermonkey（篡改猴）里运行会持续打橙色告警，而且 `@storageName`、跨标签页状态同步这些 ScriptCat 专有能力不保证。

- Chrome 应用商店搜「脚本猫」；扩展 ID `ndcooeababalnlpkfedmmbbbgkljhpjf`
- 装完**在扩展详情页打开「允许运行用户脚本」**
- ⚠️ 两个管理器同时装同一个脚本会互相抢 `.user.js` 的接管，先关掉旧的再导

### 2.2 装脚本

浏览器打开下面这个地址，脚本猫会接管 `.user.js` 并弹出安装页，点「安装」：

```
https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.user.js
```

> 必须通过 http(s) 打开才会触发安装；用 `file://` 打开只会被当成纯文本渲染。

> **下载慢？**（2026-11-25 实测）首选上面这个 jsDelivr 地址 —— **国内可直连，不用梯子**，
> 「检查更新」也走它。实测 52–141 KB/s，字节与发布件逐字节一致。
> 万一 jsDelivr 慢了，备用是 GitHub Releases（直连只有 13–25 KB/s、三轮有两轮超时），
> 或给路径套上 `https://ghfast.top/` / `https://gh-proxy.com/` 前缀（实测可用）。
> **脚本跑起来之后不需要代理** —— 它访问的题库和超星域名国内都能直连。
> 详细数据与完整备用地址见 [docs/安装与自动更新.md](docs/安装与自动更新.md) §2、§4。

### 2.3 首次配置

1. 打开超星课程章节页（`knowledge/cards`），页面会被替换成脚本面板；
2. 填两块设置（面板里左右并排）：

   | 区块 | 项 | 说明 |
   |---|---|---|
   | 答题设置 · 题库 | 题库 Token | 选填，只影响题库并发 |
   | | 正确率门槛 | 默认 80%，自动提交门槛（按答完题的比例算） |
   | | 翻章模式 | 遍历（推荐）/ 不跳转 |
   | 答题设置 · AI 接口（可选） | Base URL | OpenAI 兼容接口根地址，例 `https://api.deepseek.com/v1`。**不要带** `/chat/completions`，脚本会自动拼 |
   | | 模型 | 例 `deepseek-chat` |
   | | API Key | 你的 key。**只存在你浏览器的脚本管理器存储里**，脚本文件本身不含任何密钥 |

   填完分别点「**保存题库设置**」和「**保存AI设置**」（两块各存各的）。

3. 点「测试AI连通性」，看到 **AI连通性正常** 即可；
4. 在章节测试处打开「自动答题」+「自动提交」。
5. 想让它一路自己刷到底（遇直播/阅读不停机），在「任务配置 → 托管模式」里勾选「全程托管」。

### 2.4 用什么接口都行

任何 OpenAI 兼容的 `/chat/completions` 服务：DeepSeek、Kimi、智谱、MiniMax、通义、OpenRouter、
Ollama、本机 CLIProxyAPI 等。

> ⚠️ 推理型模型（MiniMax 等）会把**思考 token 计入 `max_tokens`**，额度给小了会返回空内容。
> 脚本已把上限放宽到 8000，并对 MiniMax 端点额外下发 `reasoning_effort: 'low'` 降思考深度。

### 2.5 调试模式（默认关闭）

需要排查问题时再开：勾选后，面板日志会**实时写到本机文件**，并且可以**从命令行远程操控脚本**。

```powershell
node src/tools/log-sink.cjs      # 接收端，默认端口 8124，日志落到 logs/

curl -X POST http://127.0.0.1:8124/__cmd -H 'Content-Type: application/json' -d '{"cmd":"status"}'
curl 'http://127.0.0.1:8124/__log?tail=50'
```

可用命令：`pause` / `resume` / `status` / `reload` / `goto <chapterId>` / `set <key> <val>` /
`log <text>` / `dump` / `help`。

> 公开版保留了这套代码，但**开关默认是关的** —— 装了脚本不会往任何地址发请求。

更详细的安装与排错见 [docs/安装与自动更新.md](docs/安装与自动更新.md)。

## 3. 自动更新怎么工作

脚本元数据里声明了：

```
// @updateURL    https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.meta.js
// @downloadURL  https://cdn.jsdelivr.net/gh/qianbkk/chaoxing-helper@main/dist/chaoxing-helper.user.js
```

发新版时把新版本提交到 `main` 分支（`dist/` 里的两个文件是提交进仓库的），
**已安装的用户点「检查更新」就能拿到新版**，元数据不用改。

**为什么走 jsDelivr（v1.11.5 起）**：「检查更新」是浏览器**直接请求** `@updateURL` 的。
GitHub 在国内快慢极不稳定 —— 实测同一个地址直连只有 461–1068 B/s，715KB 的文件三轮里有两轮
30 秒超时下载不全，于是「不挂梯子就更新不了，或者更新很慢」。
jsDelivr 是国内可直连的 CDN（实测三轮全 200），读的就是本仓库 `dist/` 里的同一份文件。

> ⚠️ **代价**：jsDelivr 走 `main` 分支有**缓存延迟**（通常几分钟到几十分钟），不是提交即到。
> 发完新版如果还显示旧版本，等一会儿再点一次「检查更新」。

GitHub Releases **照常发版**，作为 jsDelivr 走不通时的**备用通道**：
`https://github.com/qianbkk/chaoxing-helper/releases/latest/download/chaoxing-helper.user.js`
（发布流程是「先推 main，再发 Release」，否则 jsDelivr 上还是旧版。）

两个必须知道的实现细节（读脚本管理器源码 + 本机实测确认）：

1. `@updateURL` 与 `@downloadURL` **必须同时声明**，只声明一个不生效；
2. `@updateURL` 返回的内容会被当作元数据块解析，所以它必须是 `==UserScript==` 元数据块
   （`.meta.js`），不是 Greasy Fork 的 JSON —— 这就是 Release 上要挂两个资产的原因。

## 5. 开发（维护者视角）

```powershell
# 1. 改生成脚本，而不是直接改产出文件
notepad src\patches\patch-vX.Y.Z.ps1   # 版本跃迁脚本
notepad src\modules\*.js               # 整块模块源码（注意：只有 §4 里标【活】的 8 个是构建输入）
notepad src\build.ps1

# 2. 一键重建（完整性闸门 + 两个产物的语法校验）
pwsh -File src\build.ps1

# 3. 跑测试（改完必跑，十五套都指向 dist/ 里的当前发布件，合计 934 项断言）
Get-ChildItem tests\*.test.js | ForEach-Object { node $_.FullName }

# 4. 单独语法校验
node --check dist\chaoxing-helper.user.js

# 4b. 文档链接自检
node src\tools\check-links.cjs

# 5. 提交推送（必须先推 main，jsDelivr 读的就是 main 分支的 dist/）
git add -A
git commit -m "..."
git push origin main

# 6. 发版（先跑发布卫生闸门，再挂 Release 资产；Release 是 jsDelivr 的备用通道）
node tests\release-meta.test.js
gh release create vX.Y.Z --title "vX.Y.Z" --notes "……" `
    dist\chaoxing-helper.user.js dist\chaoxing-helper.meta.js
```

> ⚠️ **顺序不能反**：先推 `main`、再发 Release。反了的话 jsDelivr 上还是旧版，
> 用户点「检查更新」拿到的是上一版。jsDelivr 本身还有几分钟到几十分钟的缓存延迟。

更多细节见 [docs/开发与构建.md](docs/开发与构建.md) 与 [src/README.md](src/README.md)。
